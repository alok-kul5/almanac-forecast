Demand forecasting · MLOps

How many units will each product sell in the next two weeks?

A global LightGBM model forecasts 14 days of demand for 50 products of a UK online retailer, with P10–P90 bands. It's tested on 12 rolling backtests, versioned in an MLflow registry that only promotes models that beat the baselines, served over FastAPI and watched for drift.

Backtest: refit every two weeks, forecast the next 14 days

Each fold trains only on data before its cutoff. WAPE is total absolute error divided by total units, so it can be read as a percentage of demand. Every feature looks at least 14 days back, so one model covers the whole horizon with no leakage (a unit test checks this).

Monitoring: the last 8 weeks, replayed as if live

A model is frozen 8 weeks before the data ends. Each week we score its forecasts once actuals arrive, and compare that week's inputs against a 6-month reference window with PSI. Thresholds are calibrated on the reference window itself, so ordinary week-to-week noise doesn't raise alarms.

What the model leans on

Pipeline

CleanDrop cancellations, returns and postage codes. Zero-fill a daily panel of 50 SKUs.
FeaturesLags of 14 days or more, same-weekday means, a holiday calendar and outlier caps.
Backtest12 rolling folds against two baselines. P10/P90 quantile models.
RegistryMLflow tracking. A new version is named champion only if it beats the best baseline.
ServeFastAPI /forecast with validation and bands. Docker image built in CI.
MonitorLive WAPE and calibrated PSI. An alert recommends a retrain.

Run it

python -m venv .venv && .venv/Scripts/activate   # or source .venv/bin/activate
pip install -r requirements-dev.txt
python scripts/fetch_data.py       # UCI Online Retail II -> data/processed/panel.parquet
python -m almanac.train            # backtest, train, log + register in MLflow
python -m almanac.monitor          # 8-week drift replay
uvicorn almanac.api:app            # POST /forecast  {"skus": ["85123A"], "horizon": 14}
mlflow ui --backend-store-uri sqlite:///mlruns.db
